# 参数化CAD生成系统技术方案
## 基于参数化构造过程与几何验证的工程设计辅助系统

# 项目背景与定位

## 问题定义

相关工作处理的是不同层面的 CAD 生成问题。下表将 SKY-001 文章中展示的三类任务（不是三个独立产品）、Seek-CAD 与 FutureCAD 放在同一口径下比较。

| 工作/任务 | 主要解决的问题与模型组成 | 输入 → 输出 | 使用范围与发展方向 |
|---|---|---|---|
| SKY-001：CAD装配层级 | Hierarchical Composer逐层拆解整体与组件；Construction World Model预测叶节点的构建序列 | 产品图像等 → 装配/零件层级、2D草图与3D状态序列 | 面向复杂产品装配；官方把草图转成可执行操作和可编辑特征历史列为后续方向 |
| SKY-001：BIM构建 | Composer按规则生成单元/房间层级，Construction World Model按顺序生成平面图状态 | 建筑轮廓/布局 → 房间层级与逐步平面图 | 面向建筑平面布局；重点是空间布局与绘制序列，不等同于机械零件参数化建模 |
| SKY-001：CAD零件构建 | Construction World Model预测零件的中间3D状态及状态之间的2D草图 | 零件/父级上下文 → 草图和逐步3D视觉状态 | 展示复杂零件的视觉构建过程；当前公开介绍指出，可执行操作与可编辑特征历史仍待发展 |
| Seek-CAD | 不微调生成主模型；DeepSeek-R1配合SSR规则、CAD代码检索和逐步视觉反馈生成并修订建模程序 | 自然语言 → SSR组织的CAD代码、执行后的模型 | 探索检索增强的参数化建模与反馈修正；依赖检索语料、CAD执行环境及视觉反馈服务 |
| FutureCAD | Qwen2.5-7B经SFT/RL生成CadQuery程序；BRepGround将文字查询定位到当前B-Rep中的边/面 | 零件描述 → CadQuery程序及执行实体 | 聚焦零件级生成和圆角/倒角/抽壳等拓扑选择；扩展到新领域仍需相应数据与验证 |

本项目要解决的是更窄的工程问题：针对**一个经数据核验后冻结的零件族**，把文字需求转成可检查的参数、依赖和约束，由确定性CAD构造器生成可编辑模型，并验证参数修改后特征关系是否保持。它不复现SKY-001的视觉世界模型，不复制Seek-CAD的通用代码自修订路线，也不以训练通用模型完成任意零件生成作为目标。后续方向是先验证单一零件族的参数化闭环，再依据新增数据和独立测试决定是否扩展到相邻零件族、更多输入形式或学习式构造模块。

## 首期候选零件族与决策门

| 候选方向 | 数据获取与适用场景 | 主要生成难点 | 初步判断 |
|---|---|---|---|
| 工业铝型材框架角码／连接板 | 厂商目录、尺寸表和部分CAD较容易查找；用于设备机架、防护围栏、工装台及机器人工作站框架 | 型材槽宽/系列、连接方式、孔槽布局和配套紧固件接口需匹配；首期可限定少数系列 | **建议优先验证**：数据较结构化、几何规则相对明确，较适合作为低风险基线 |
| 机器人末端工具安装转接板 | 机器人法兰及夹爪/吸盘厂商资料、部分CAD可查；用于末端工具换装和接口适配 | 不同品牌/型号法兰孔系与工具接口组合多，中心定位、螺纹/通孔和厚度约束需明确 | 用途价值高，但接口数据分散；适合作为数据核验通过后的备选 |
| 电机安装板／支架 | 厂商样本、安装尺寸表和部分CAD可查；用于电机固定及设备集成 | 需处理轴线对中、孔距、底脚/法兰安装方式、间隙等装配关系 | 有明确需求，但装配约束较复杂，首期生成边界需收紧 |

决策门：结合数据可得性与使用许可、参数规则清晰度、几何生成可控性和场景价值，检查真实样本及CAD内核试跑结果后冻结一个方向。此表是待核验的初步判断，不代表已完成数据审计；如果铝型材连接件的规格/许可或可验证数据不足，应选择得分更高的备选方向。三个候选只做比较，不并行建设三套模板。具体推进安排另行与导师讨论。

# 方案A：完整版（Full Version）

## 技术定位

在12周内完成候选方向筛选，并对最终选定的单一零件族实现参数化CAD生成与可编辑性验证；同时完成有界的监督微调对照和强化学习可行性实验。候选方向和数据来源经决策门冻结，后续测试集与指标随之锁定；具体决策时间由项目组与导师商定。核心目标：
1. **参数化生成**：输出可编辑的参数化设计而非固定序列
2. **领域专业化**：在经数据核验后冻结的一个零件族内验证几何与接口规则
3. **小样本适配评估**：比较检索/上下文示例与有界LoRA/QLoRA监督微调，并验证CAD执行奖励用于RL的可行性；不宣称元学习或新零件族泛化

**12周范围约束**：完整版是单一零件族上的研发验证，不是多领域产品。范围内必须完成：①云端与本地模型基线对照；②构建并审计一个小型CAD样本/检索数据库，明确来源、许可、参数真值和分组切分；③在数据集、基线与确定性CAD闭环准备就绪后，完成一次有界的LoRA/QLoRA监督微调对照；④完成一次小规模RL可行性实验，检验CAD执行奖励相对SFT、检索和规则验证是否提供可测增益。实验样本量、rollout上限、硬件时长和停止条件先通过小试跑确定并记录；这里要求的是可复现的受控实验和明确结论，不承诺大规模训练或必然提升。如果数据、奖励信号或执行吞吐未达到预设最低门槛，仍须完成并报告门槛试验、失败原因和“当前条件下不可判定/不值得继续”的结论，不扩大训练、不挤占确定性闭环交付。首期不做从零预训练、1B级自建解码器、万级rollout、通用CAD大语料建设、多零件族并行交付或工业级仿真认证。

## 系统架构

以下在线生成主干由完整版与轻量版共用；两版的区别在于主干之外的研发实验范围，不是两套不同的CAD生成系统。完整版增加的数据构建、模型适配和RL评估属于离线研发流程，实验结论可用于决定是否更新在线系统中的模型或检索配置。

### 整体流程

```
用户输入
  ├─ 文本描述（自然语言需求）
  ├─ 参考图像（可选）
  └─ 示例零件（小样本模式）
    ↓
[结构化意图理解层]
  ├─ 云端/本地LLM结构化抽取
  ├─ 可选图片线索（只产生候选，不推断精确尺寸）
  └─ 字段来源与缺失项标记
    ↓
[Schema与规则校验]
  ├─ JSON Schema / Pydantic
  ├─ 单位归一化与参数边界
  └─ 缺失关键输入时追问
    ↓
[Typed CAD IR与确定性编译器]
  ├─ 特征节点、参数、依赖和约束
  ├─ 白名单CadQuery操作
  └─ 运行日志与版本化记录
    ↓
[CAD内核与验证器]
  ├─ CadQuery / OCP几何构造
  ├─ B-Rep与STEP回读检查
  └─ 规则断言与有界修复
    ↓
输出
  ├─ 可编辑CadQuery构造记录
  ├─ STEP几何交换文件
  └─ 参数、约束、校验报告与版本信息
```

**版本差异（离线研发流程）**：完整版在共同主干之外，构建并审计单一零件族CAD数据库，开展云端/本地基线评测、有界QLoRA对照及小规模RL可行性实验；这些实验不替代Typed CAD IR、确定性编译器或CAD内核验证。轻量版不把QLoRA、RL和专门的训练管线纳入主线交付，只使用选定的云端或本地模型、规则和小型检索库完成同一在线主干。

### 核心组件设计

#### 组件1：多模态意图理解

**输入处理**：
- 文本：自然语言需求；首期主路径
- 图像：参考照片/草图仅作为补充线索，不据此推断无尺度依据的精确尺寸
- 示例零件：优先使用已标注参数的CAD样本检索；图片检索只用于召回候选

**模型选择与部署**（候选版本以开工时可用的官方API/权重为准）：

**为什么同时保留云端和本地基线**：两者回答不同的研发问题，使用同一冻结测试集和相同字段口径比较，避免只看到某一类模型的表现就误判系统瓶颈。云端基线代表较强通用模型在低部署负担条件下的性能参照，用来估计参数抽取、缺失信息识别等任务的可达到水平，并验证问题是否主要出在模型理解；本地基线代表可控成本、数据本地化和后续适配的可部署参照，用来评估小模型加Schema/规则能否满足需求，并作为LoRA/QLoRA训练前后的对照。最终不是默认云端或本地胜出，而是按准确率、拒绝/追问质量、Schema通过率、延迟、账单/显存和许可综合选择，也可采用云端开发基线、本地部署模型的分工。

**云端基线**：若GPT-6.1/GPT-6在项目启动时可通过官方端点使用且支持所需的结构化输出，应优先纳入候选横评；GPT-5.5只作为已有RealCADBench结果可供参照的历史对照，不因论文评测过就默认优于新版本。记录具体模型ID、地区可用性、功能、价格和评测日期。

**本地基线**：[Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)代表较低资源档，用于测试轻量推理和本地部署；[DeepSeek-R1-Distill-Qwen-14B](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-14B)代表更强推理但更高资源档，用于判断复杂约束理解是否随模型能力提高。二者构成性能—成本参照，不是预先认定的最佳模型；若开工时有更新且许可合适的权重，可在相同测试集上替换或补充。先核验许可、量化格式、上下文显存和结构化输出能力。图像不是首期主路径。

**实现原则**：首版是文本优先的结构化抽取与确定性CAD生成，不建设单独的跨模态融合网络或视觉编码器；如果后续把图像作为正式输入，再单独评估视觉模型和融合方案。模型输出受JSON Schema约束的字段；Pydantic负责Python数据类型与字段校验，Pint负责物理单位换算与检查。显式给定值、系统默认值和模型候选值必须分开标记；承载力、材料、荷载等关键输入缺失时追问，不自动补成工程结论。只给用户可核验的简短依据，不要求模型输出隐藏的逐步思维链。

#### 组件2：参数提取与推断

**功能**：从意图表示中提取结构化参数定义

**输出格式**：
```json
{
  "part_type": "connection_plate",
  "parameters": {
    "width": {
      "value": 150.0,
      "unit": "mm",
      "range": [100.0, 300.0],
      "inferred": false
    },
    "thickness": {
      "value": 12.0,
      "unit": "mm", 
      "range": [8.0, 25.0],
      "inferred": false
    },
    "hole_diameter": {
      "value": 17.0,
      "unit": "mm",
      "range": [10.0, 24.0],
      "inferred": true,
      "inference_reason": "standard_M16_clearance"
    }
  },
  "constraints": [
    {"type": "min_edge_distance", "value": "2 * hole_diameter"},
    {"type": "thickness_ratio", "expression": "thickness >= hole_diameter * 0.5"}
  ]
}
```

**模型架构**：
- 类型：现成LLM结构化抽取 + schema校验 + 确定性规则引擎
- 不单独训练100M参数解码器；数据量和首期单零件族范围不足以支持该复杂度
- 完整版按范围完成一次有界LoRA/QLoRA对照；是否扩大适配规模由基线差距、数据质量和停止条件决定

#### 组件3：参数化序列生成

这一组件是从“已经校验的参数”到“可以交给CAD后端执行的建模准备”的关键环节。它不让LLM直接自由生成任意CadQuery/Python代码，而是先用版本化的Typed CAD IR表达特征节点、参数、单位、依赖边和约束；再由确定性编译器把IR转换为受限的CadQuery操作序列。这样，模型负责提出结构化的建模意图，编译器负责按固定规则组织操作，CAD内核负责实际构造几何，后续验证器再检查构造结果是否有效。参数引用、特征依赖和约束会在这一阶段显式保存，便于同一零件族进行参数修改、失败定位和结果复现。

**核心创新**：生成带参数引用的操作序列，而非固定值

**朴素的固定值操作序列示意（仅用于说明参数化差异，不代表SKY-001的实际实现）**：
```python
operations = [
  {"type": "sketch", "plane": "XY"},
  {"type": "rectangle", "width": 150, "height": 150},  # 固定值
  {"type": "extrude", "distance": 12}  # 固定值
]
```

**参数化方式（本项目）**：

下方连接板JSON和CadQuery片段仅用于演示参数引用与代码组织；它们不是最终零件族的决定，也不预设将做钢结构。待零件族选型冻结后替换为对应族的参数Schema与构造器。
```python
operations = [
  {"type": "sketch", "plane": "XY"},
  {"type": "rectangle", 
   "width": {"ref": "params.width"},  # 参数引用
   "height": {"ref": "params.height"}},
  {"type": "extrude", 
   "distance": {"ref": "params.thickness"}}
]
```

**生成架构**：
- 用版本化Typed CAD IR表达特征节点、参数、单位、依赖边和约束，不让模型自由输出任意CadQuery/Python代码。
- IR由确定性编译器映射到单一CAD后端（首期CadQuery 2.8.x/OCP）；只开放白名单操作，并在构造前后运行参数与几何校验。
- 交付物区分：参数化CadQuery脚本保存本项目内的可编辑构造过程；STEP用于几何交换，不承诺在接收端保留原生特征树。若必须交付原生特征历史，需改选并验证FreeCAD文档格式（FCStd），不要把STEP等同于特征历史。

**模型实验与训练边界（完整版）**：
- 先在同一测试集上建立云端/本地基线；另行构建可追溯的小型CAD数据库，服务于检索、监督微调和RL奖励评测，按零件ID/模板族分组切分，避免近重复泄漏。
- 对一款开源7B/8B模型完成有界LoRA/QLoRA监督微调对照；14B仅在实际显存、数据和时间试跑通过后考虑。报告训练前后字段、约束和CAD成功指标，不把模板变体数量当作有效独立数据量，也不把“基线差距小”当作跳过对照的理由。
- 在构造器、执行环境与验证器稳定后，完成一个小规模RL可行性对照：以CAD执行成功和明确几何/约束奖励为信号，比较SFT与SFT+RL；先用短rollout试跑估计奖励噪声、每样本耗时、有效样本率和显存，再锁定封顶预算。若最低门槛未通过，结论可以是“当前资源/数据下不可判定或不值得继续”，不强行把RL接入最终系统。
- 不训练500M–1B自建解码器、不做从零预训练、不跑万级rollout、不用同一模板近重复变体宣称泛化，也不建设覆盖多个行业的通用CAD数据库。系统主路径仍由Typed IR、确定性编译器和内核验证保证可检查性。

#### 组件4：小样本检索适配层

**技术路线**：检索增强的上下文示例（不称为元学习）

[Seek-CAD](https://arxiv.org/abs/2505.17702v3)研究本地LLM的视觉/文本反馈自我修正；其论文版本和会议状态应按 arXiv/会议页面分别记录。[FutureCAD](https://arxiv.org/abs/2603.11831)是2026年3月发布、4月更新的预印本，研究CadQuery程序生成与B-Rep原语定位。两者都不是少量样本即可学会新几何族的证据。新近的[CADIR](https://arxiv.org/abs/2608.00891)和[ReliCAD](https://arxiv.org/abs/2609.22325)预印本进一步强调显式构造表示、意图建模和运行时验证；其指标为作者报告，需独立复现。

**工作原理**：
```
用户提供3-5个带参数的参考零件（CAD文件优先；只有图片时仅做外观检索）
    ↓
系统在最终选定零件族的模板/参数空间内检索相似样本
    ↓
展示参考样本及其参数，不把样本直接当成新的几何规则
    ↓
用户确认后由确定性特征图生成新参数化设计
```

**技术实现**：
- 首版按归一化尺寸、孔数/布局、特征类型和CAD内核导出的几何描述符做检索；样本量较小，不需要部署PointNet++/RegDGCNN。
- 对比无样本、检索样本和人工选模板三种条件；度量参数准确率、约束通过率和建模时间。
- 只有评估显示检索在未见参数组合上有稳定收益，才保留该模块；不声称从少量示例适配任意新零件族。

## 数据与样本构建

### 数据规模估算

候选比较阶段评估三个方向并冻结一个首期零件族：①工业铝型材框架角码／连接板（目录和尺寸规格较易获得，生成规则相对规整，适用于设备机架、防护围栏、工装台和机器人工作站框架）；②机器人末端工具安装转接板（机器人法兰与夹爪、吸盘等工具之间的接口适配件，应用明确，但不同品牌/型号接口组合分散）；③电机安装板／支架（厂商目录和部分CAD可得，但安装孔位、轴线对中和装配间隙约束较多）。这里只做候选比较，不把三个方向同时作为训练或交付范围。首选建议为铝型材框架连接件，前提是候选核验阶段能取得足够的合法尺寸/接口资料；若数据核验不通过，再按同一评分表选次优方向。

先完成100个可审查实例的试跑，覆盖合法参数边界、典型拓扑、缺失输入和非法约束。随后按评测目标与实际吞吐决定是否扩至200–500个；800–1500个不是首期前置要求，只在自动生成可靠、且需要更细的参数组合覆盖时追加。数据按参数族/拓扑分组切分，避免近重复泄漏；测试集保持人工核验。QLoRA数据只在确有训练实验时另行确定，不能把合成样本数等同于有效训练数据量。

每个样本至少包含：参数JSON、Typed CAD IR、CadQuery脚本、CAD内核校验结果、STEP几何交换文件、固定视角渲染图、约束断言结果和来源/版本元数据。材料强度、荷载和规范条文不从几何样本中自动推断。

### 数据生成流程

**自动化pipeline**：

```python
def generate_parametric_sample(part_type: str, param_ranges: Dict):
    """
    生成单个参数化样本
    """
    # 1. 随机采样参数（在合理范围内）
    params = sample_parameters(param_ranges)
    
    # 2. 生成参数化操作序列（CadQuery）
    operations = generate_cadquery_code(part_type, params)
    
    # 3. 执行验证
    cad_model = execute_cadquery(operations)
    is_valid = validate_geometry(cad_model)
    
    if not is_valid:
        return None
    
    # 4. 生成多模态表示
    step_file = export_step(cad_model)
    images = render_multiview(cad_model, angles=[0, 45, 90, 135])
    
    # 5. 生成可复现的结构化描述；自然语言仅作为可选评测输入
    description = render_deterministic_description(params, part_type)
    
    return {
        "params": params,
        "operations": operations,
        "step_file": step_file,
        "images": images,
        "description": description
    }
```

**质量控制**：
- 几何检查覆盖率：CAD内核、实体闭合性、非零体积和STEP回读均执行；失败样本保留失败原因，不把丢弃样本计入成功率。
- 参数合理性：单位归一化和规则检查100%，工程师抽查至少10%；抽查比例与风险一起记录。
- 描述准确性：优先使用确定性模板；若加入LLM改写，必须与结构化真值逐字段比对。
- 去重与泄漏检查：按参数组合、接口类型、特征拓扑和几何结构分组后再划分，不能把同一模板的近邻变体拆到训练和测试两侧。

### 数据集划分

```
开发集：用于模板、规则与提示迭代
验证集：用于方案选择与停止条件
最终测试集：冻结后封存，仅用于最终评估
若样本量不足以稳定训练/验证切分，仍完成封顶的适配可行性试验，但将结果标注为探索性，不作泛化结论；采用分组留出测试并明确统计不确定性。RL试验另受奖励信号和执行吞吐门槛约束。

测试集特殊设计：
- 按参数空间、接口类型和特征拓扑分组留出，覆盖边界与未见组合
- 包含组合约束、单位换算和缺失参数测试样本
- 另设一组人工编写的“分布外”用例，只用于失败分析，不计入主指标
```

## 计算资源估算

### 硬件需求

**建议按两条路径配置**：
- **确定性系统主线（推荐交付路径）**：确定性CAD、规则校验和检索主要使用CPU；API模型路径也不要求本地GPU。开发机建议8–16核CPU、32–64GB内存、约1TB NVMe。16核/64GB是多人并行生成与渲染的舒适配置，不是最低门槛。
- **本地推理与训练实验**：已有A100 80GB可用于本地模型对照、QLoRA及短程RL试跑，但不是系统运行依赖。RTX 5090（32GB）可作为单卡量化推理/小规模QLoRA候选；14B模型需按实际序列长度、量化和训练框架先测峰值显存。96GB级工作站卡只在确有更大模型或并发需求时考虑。H100不列为首期需求。
- 以上显存规格只说明卡的容量，不直接推出训练时长或模型性能；吞吐须用本项目数据和固定配置实测。首期不建设视觉融合器或从零训练解码器；数据库检索、CAD执行和奖励计算的并发需求按试跑吞吐估算。

**资源口径**：CPU负责CadQuery/OCP几何构造、数据整理和渲染任务；可以先用现有工作站试跑，再按并行任务数扩容。存储预留1TB NVMe用于模型缓存、CAD样本、渲染图、日志和检查点，实际占用在100样本试跑后复核。

### 训练时间估算

**数据准备与数据库构建**：先筛选方向，再对100个实例实测CAD构造、渲染和校验耗时；只有自动生成和核验稳定后，才按实际并行吞吐评估是否扩到200–500个。预留失败重试和人工抽查时间，比例由试跑记录估计，不预设30%或固定总量。不要把LLM描述生成计入必需路径。

**模型与RL试验（纳入完整版范围）**：先完成云端/本地基线和小型CAD数据库，再执行一次封顶的7B/8B QLoRA对照；在CAD执行、奖励定义和验证器稳定后，完成短程RL可行性试验。先用小样本测训练/rollout吞吐、奖励有效率、峰值显存和失败重试，再确定实验上限；必须报告结果和停止依据，不承诺预设训练时长或RL提升。

训练时长按实测外推：`单轮计划步数 = ceil(训练样本数 / 有效batch大小) × epoch数`；`GPU小时 ≈ (单步平均秒数 × 单轮计划步数 × 试验轮数 + 验证/保存/启动总秒数) / 3600`。其中训练样本数是切分后的训练部分，有效batch需包含梯度累积；数据打包、padding和序列长度会显著改变单步时间。**不预设固定A100小时数**，完成小试跑后才形成预算和停止上限。GPU小时是“某一型号GPU占用一小时”，不同型号之间不能按小时数直接等价换算；跨卡比较应测同一训练配置的实际完成时间和租用账单。

若实验室没有GPU：API基线和确定性CAD主线仍可运行；为完成完整版范围内的QLoRA与RL可行性实验，可短租云端单卡GPU，先用小试跑确认峰值显存、CAD奖励吞吐和费用，再运行封顶实验并保存环境/日志。32GB级消费卡可尝试7B/8B的4-bit QLoRA，通常需缩短序列、减小micro-batch并增加梯度累积；RL rollout的CAD执行更依赖CPU并行，显卡本身不能消除该瓶颈。CPU-only可执行CAD和量化推理，但不适合完成有代表性的微调/RL对照；若经费或试跑吞吐不足，应完成门槛试验、记录未达可判别条件的证据，并与导师商定替代验证方式。

**范围控制**：不安排融合器预训练、500M–1B自建解码器、从零预训练或万级强化学习rollout。完整版仅做有界的监督微调与RL可行性对照；CAD内核执行检查、B-Rep有效性、约束断言和最多一次自动修复仍是交付闭环的确定性基础。

### 推理资源估算

**推理资源**：分开记录模型端到端延迟、CAD内核执行、渲染和人工确认；在固定硬件、上下文长度和并发数下报告P50/P95，不预先承诺固定秒数或吞吐。交互Demo采用异步任务和进度状态。

## 技术验收指标

### 主要指标

指标在候选方向冻结后，按该零件族的输入字段和合法性规则细化；两版使用相同测试集、数据切分和统计口径。成功率同时报告“合法输入上的构造成功率”和“包含拒绝/追问的端到端成功率”。

| 指标 | 测量方法 | 目标值 | 基线对比 |
|------|---------|--------|---------|
| **参数提取准确率** | 按字段统计；尺寸、单位、接口/特征布局分别报告，测试集按参数组合分组 | 先建立基线，再以预注册目标为准 | 不引用未经复现的人工一致性或论文数字 |
| **输入判定正确率** | 合法输入接受、非法/缺失关键输入拒绝或追问的正确比例 | 建立基线后冻结目标 | 分开报告拒绝率与误接受率 |
| **构造可执行率** | IR编译并运行CadQuery成功的比例 | ≥95% | 与自由代码生成基线同批测试 |
| **合法输入几何有效率** | 在标注为可构造的合法输入中，CAD运行成功且STEP回读、闭合性、非零体积均通过的比例 | ≥95% | 另报全体输入的端到端成功率；几何有效不等于结构安全 |
| **约束保持率** | 固定测试集对参数做100次合法/非法修改，断言结果与预期一致 | ≥98% | 记录拒绝非法输入的原因 |
| **检索增益** | 检索样本相对无样本的字段准确率和人工修改次数差异 | 只有置信区间不跨零才纳入主流程 | 不把小样本增益写成泛化保证 |

### 失败情况分析

**预期失败模式**：
1. 极端参数组合（如特征间距不足、壁厚或边距超出定义范围）
2. 冲突约束（用户同时要求最小尺寸和最大孔数）
3. 超出训练域的零件类型
4. 模糊或歧义的自然语言描述

**处理策略**：
- 系统明确拒绝并说明原因（不自动编造）
- 提供参数调整建议
- 允许用户手动修正参数

# 方案B：轻量版（Lean Version）

## 技术定位

采用无训练交付主线，利用开工时横评选定的LLM推理能力和有界验证反馈，实现经候选评估后选定的单一零件族参数化CAD生成。核心特点：
1. **无训练交付主线**：使用API或开源模型零样本/检索增强推理；QLoRA/RL只做独立可行性对照，不并入交付
2. **可验证流程**：结构化抽取、Typed IR、CAD内核和规则验证形成闭环
3. **确定性生成**：LLM先输出受Schema约束的参数候选，再转换为Typed CAD IR；CAD生成部分使用白名单模板和确定性编译器，成功率以测试集实测，不宣称100%保证

---

## 技术方案：基于Seek-CAD范式的改进

### 核心思想

参考[Seek-CAD](https://arxiv.org/pdf/2505.17702v3)（2025-05预印本，v3于2026-02更新）的训练无关方法论，并吸收[FutureCAD](https://arxiv.org/pdf/2603.11831)（2026-03发布、2026-04更新的预印本）对程序生成与B-Rep grounding的讨论；两者的训练规模和指标不直接外推到本项目。

**关键创新**（相比传统LLM直接生成）：
1. **有限修复循环**：生成→内核/规则验证→针对字段修复
2. **结构化证据**：输出字段来源、假设和缺失信息，不要求暴露隐藏思维链
3. **Hybrid Generation**：LLM负责参数候选和结构化意图，Typed CAD IR负责承载特征/依赖/约束，确定性模板与编译器负责CAD生成

### 系统架构

本节流程与完整版“系统架构—整体流程”共用同一在线生成主干。轻量版不另建一套CAD构造架构；区别仅在于不纳入完整版的离线训练与RL实验流程。

```
用户输入（文本；参考图像或带标注样本为可选补充）
    ↓
[LLM结构化意图理解：云端或本地模型]
    ↓
[Schema与规则校验：字段、单位、参数边界、缺失项追问]
    ↓
[Typed CAD IR与确定性编译器：特征、参数、依赖、约束]
    ↓
[CadQuery / OCP几何构造]
    ↓
[CAD内核与验证器：B-Rep、STEP回读、规则断言；有界字段修复]
    ↓
输出：参数化CadQuery构造记录、STEP几何文件、参数与验证报告
```

轻量版使用相同的结构化输入、参数校验、IR、编译器和CAD验证模块；可用小型检索样本库辅助参数抽取，但不建立模型训练或RL奖励优化的在线依赖。完整版的训练数据、QLoRA和RL评测在离线研发流程中独立运行，只有经共同测试集验证有收益后，才考虑更新在线推理模型或检索配置。

**Prompt、Typed CAD IR与代码模板的关系**：Prompt不是CAD建模格式，而是给LLM的任务说明，要求它提取参数、标记来源、识别缺失项并输出符合Schema的结构化结果。该结果随后由程序转换为Typed CAD IR；IR才是在线生成主干中连接“模型理解”和“CAD构造”的内部接口，记录特征节点、参数、单位、依赖和约束。轻量版中的CadQuery代码块是确定性编译器或零件族模板的实现示例，不是让LLM自由生成并直接执行的代码。实际链路是：`Prompt → 结构化参数 → Typed CAD IR → 白名单CadQuery操作 → CadQuery/OCP → 几何与规则验证`。因此，轻量版不训练模型，但仍使用Typed CAD IR；它只是把IR的生成主要交给Prompt+Schema+规则，而不是交给QLoRA或RL训练后的模型。

## 核心技术组件

### 组件1：LLM推理引擎

**为什么同时保留云端和本地基线**：云端模型作为低部署负担的强能力参照，回答“这组结构化抽取任务在模型能力较强时能做到什么程度”；本地模型作为成本可控、便于数据本地处理和后续适配的部署参照，回答“更小模型加Schema/规则是否足够”。二者必须在同一测试集上比较，云端/本地差异才能帮助定位模型能力与系统规则的瓶颈。选择以字段准确率、拒绝/追问质量、Schema通过率、延迟、账单/显存和许可为依据；最终可以选一条部署路径，也可以云端做参照、本地做交付。

**模型选择**（候选清单，开工时锁定版本）：
- **云端基线**：若官方端点可用，将GPT-6.1/GPT-6与一个成本对照放入同一评测；GPT-5.5可作为已有RealCADBench结果的历史参照，不直接作为首选。记录实际模型ID和评测日期。
- **本地基线**：Qwen3-8B代表较低资源档，DeepSeek-R1-Distill-Qwen-14B代表较强推理但更高资源档，目的是比较性能—成本曲线；它们不是已证明的最优模型。若有更新且许可可接受的权重，以同一评测替换或补充。图像不是首期主路径。
- **资源建议**：轻量版优先API或7B/8B量化推理；A100 80GB用于对照或可选QLoRA/RL可行性试跑即可，不是系统依赖。所有成本以实际账单/日志核算。

**Prompt设计**：

USER_PROMPT_TEMPLATE = """

**这两个 Prompt 的作用**：`SYSTEM_PROMPT` 是稳定的系统级任务说明，规定模型只能提取明确参数、标记字段来源、识别缺失信息并遵守项目规则；`USER_PROMPT_TEMPLATE` 是每次请求的任务模板，把当前用户需求填入后要求模型执行零件识别、参数提取、缺失项判断和约束检查。Prompt 的输出是参数 JSON，不是 CAD 几何，也不是允许模型自由执行的 Python/CadQuery 代码。后续程序会用 Schema/Pydantic 校验这个 JSON，再把它转换为 Typed CAD IR。轻量版依靠 Prompt、Schema、规则和确定性模板完成这一步，不需要训练模型参数。

### 组件2：有限验证与字段修复循环

**参考CAD生成研究中的执行反馈机制**：

```python
def self_refinement_loop(user_input: str, max_attempts: int = 2):
    """
    有界的验证与修复循环
    """
    for i in range(max_attempts):
        # 第1步：LLM推理
        params_json = llm_infer(user_input)
        
        # 第2步：把结构化参数转换为Typed CAD IR，再通过白名单编译器构造CAD；
        # 不执行模型自由生成的代码
        build_error = None
        typed_ir = None
        try:
            typed_ir = compile_params_to_typed_ir(params_json)
            step_file = build_from_typed_ir(typed_ir)
        except CadBuildError as exc:
            step_file = None
            build_error = str(exc)
        
        # 第3步：渲染多视图
        images = render_multiview(step_file) if step_file else []
        
        # 第4步：先由CAD内核和规则验证器判定尺寸、拓扑和约束
        check = validate_ir_and_geometry(typed_ir, step_file, build_error=build_error)
        if check["passed"]:
            return cad_script, params_json
        
        # 第5步：把机器可读的失败字段返回给LLM；视觉模型只作外观辅助
        params_json = revise_only_failed_fields(params_json, check["issues"])
    
    raise GenerationRejected(check["issues"])
```

**这段循环的作用**：它是一次请求内的有限验证流程，不是强化学习。模型先输出参数 JSON，程序将其转换为 Typed CAD IR，再交给白名单编译器和 CAD 构造器；构造结果经过内核、B-Rep、STEP 和零件族规则检查后，如果失败，只把机器可读的失败字段反馈给模型修复。最多尝试固定次数，仍失败就返回可解释的拒绝原因。这样可以修复当前请求，同时避免模型直接生成并执行任意代码，也避免无限重试。`render_multiview` 和可选 VLM 只辅助外观/语义一致性判断，不负责精确尺寸、强度或几何安全性。

**关键点**：
- VLM只用于参考图像/渲染图的外观和语义一致性辅助，不判定尺寸、强度或几何安全性；几何正确性由CAD内核、Typed IR和规则验证器判定。
- 默认最多2次自动修复，记录每次输入、IR、日志和修复原因；是否增加尝试次数由固定测试集的收益决定，不能引用“3次后基本收敛”作为普遍保证。

### 组件3：确定性CAD生成器

**CadQuery确定性构造器**：

```python
import cadquery as cq

def build_connection_plate(p: dict, step_path: str):  # 连接板示例；选型后需替换为冻结零件族的构造器
    p = validate_and_normalize(p)
    rows, cols = p["hole_rows"], p["hole_columns"]
    xs = [(i - (cols - 1) / 2) * p["pitch_x_mm"] for i in range(cols)]
    ys = [(j - (rows - 1) / 2) * p["pitch_y_mm"] for j in range(rows)]
    points = [(x, y) for y in ys for x in xs]

    if any(abs(x) + p["hole_diameter_mm"] / 2 + p["edge_margin_mm"] > p["width_mm"] / 2 for x, _ in points):
        raise ValueError("hole pattern violates horizontal edge margin")
    if any(abs(y) + p["hole_diameter_mm"] / 2 + p["edge_margin_mm"] > p["height_mm"] / 2 for _, y in points):
        raise ValueError("hole pattern violates vertical edge margin")

    plate = cq.Workplane("XY").box(p["width_mm"], p["height_mm"], p["thickness_mm"])
    cutters = (cq.Workplane("XY").pushPoints(points)
               .circle(p["hole_diameter_mm"] / 2)
               .extrude(p["thickness_mm"] + 2, both=True))
    plate = plate.cut(cutters)
    if not plate.val().isValid():
        raise ValueError("CAD kernel reported an invalid solid")
    cq.exporters.export(plate, step_path)
    return plate
```

**这段 CadQuery 代码的作用**：它是某一候选零件族的确定性构造模板，不是让 LLM 每次临场编写的脚本。输入参数经过归一化和边界检查后，模板计算孔位、检查边距，使用 CadQuery 创建板体和切削体，再通过布尔运算得到带孔连接板，最后检查实体有效性并导出 STEP。实际系统中，Typed CAD IR 的特征节点会由确定性编译器映射到这类白名单模板；相同的 IR、参数和软件版本应得到可复现的构造过程。示例中的连接板仅用于说明参数如何进入几何操作，候选零件族冻结后需要替换成对应的构造器。

**边界与优势**：
- 模板路径可复现；每次运行仍需执行CAD内核、STEP回读和规则检查，不能预先承诺100%有效。
- 用户可导出参数化CadQuery脚本进一步编辑；STEP只承诺几何交换，不承诺接收端保留特征树。

## 计算资源估算

### 硬件需求（最小配置）

**GPU**（可选）：
- API模型路径不需要本地GPU；本地7B/8B量化推理可用现有消费级GPU或实验室卡，CPU也能运行但响应会更慢。
- 轻量版交付不要求QLoRA/RL。若开展独立可行性实验，按小样本试跑和GPU小时外推方法估算；没有实验室卡时可短租云GPU，资源不足时可取消这两项而不影响系统交付。

**CPU**：
- 建议8–16核；并行生成/渲染较多时再提高核心数。
- CadQuery执行时间在目标机器上实测并记录P50/P95，不在方案中承诺固定秒数。

**存储**：
- 代码和模板：<1GB
- 测试数据、渲染缓存和日志按实际产物预留1TB NVMe；STEP和图片采用压缩及去重，避免用“200个×100MB”推导不实容量。
- 参考样本库：按文件大小实测，首期可保持在数GB以内。

### API成本估算（如果不本地部署）

不写死模型名称或单价。根据固定测试用例数、每次请求的输入/输出token、重试次数和供应商当日账单计算：

`总成本 = Σ(输入token × 输入单价 + 输出token × 输出单价) + 图像/工具调用费用`

把账单截图或API usage导出、模型版本、日期和失败重试次数随实验记录保存。若成本超预算，先减少VLM调用和上下文长度，再切换本地7B/8B对照。

# 两版本技术对比

## 关键差异

| 技术维度 | 完整版 | 轻量版 |
|---------|--------|--------|
| **模型训练** | 可选QLoRA短试验；不作为主线 | 不需要训练主线 |
| **数据准备** | 先100个试跑，再按收益与吞吐扩展；训练集可选 | 同一冻结测试集；检索数据规模按来源核验确定 |
| **核心技术** | Typed IR、内核验证与可选适配 | LLM推理+确定性模板 |
| **GPU需求** | 主线不要求GPU；QLoRA可用本地卡或短租云GPU | API路径无需GPU；本地推理可选 |
| **实施风险** | 中等（适配收益不确定） | 较低（范围窄，仍需实测验证） |
| **可扩展性** | 中（IR/数据管线可复用，跨族需重新验证） | 中（需手工扩展模板） |
| **研究特点** | 可选参数适配对照，不预设新架构收益 | 结构化抽取、确定性构造与执行反馈 |

## 技术选择依据

### 选择完整版的理由

1. **长期技术积累**：保留版本化IR、验证器和数据生成管线，为后续零件族扩展打基础
2. **研究对照**：在确有数据和基线差距时，评估适配是否改善参数抽取；不预设训练必然带来泛化
3. **研究价值**：可形成关于结构化意图、确定性CAD与内核验证的可复现实验；是否发表取决于结果和贡献
4. **训练与RL实验有界纳入**：完整版要求完成QLoRA对照和RL可行性实验；若本地资源不足，可通过短租GPU完成封顶试验，或在门槛试验后记录不可判定结论

### 选择轻量版的理由

1. **快速验证**：首轮验证阶段就知道可行性
2. **低训练成本**：把时间用于闭环、评测和工程交付
3. **技术前沿**：采用执行反馈、显式意图和可编辑IR等近期方向
4. **更高可控性**：确定性模板降低输出方差，但仍由内核验证兜底
5. **灵活性**：更容易根据反馈快速调整

# 总结

本技术方案提供两个可行的实施路径。对12周、零件族尚未最终确定且GPU并非必备的当前条件，建议以轻量版作为低风险交付主线；完整版额外要求构建可追溯数据集并完成封顶的QLoRA对照和RL可行性实验，保留同一套评测、IR和验证资产。

**完整版**聚焦可复现实验方法：先比较三个候选并冻结一个零件族，再用Typed IR和CAD内核验证参数化CAD闭环；在封顶预算内完成QLoRA对照和RL可行性实验，结果不预设为正向，硬件不足时通过短租GPU或记录门槛未通过来收束结论。

**轻量版**采用结构化抽取、检索和有限执行修复，结合确定性模板降低实现风险，适合在12周内交付可演示系统。

两个版本共同的核心创新是**参数化可编辑性**，这是SKY-001公开文章列为后续工作的方向。无论选择哪个版本，都应以可复现的内核验证和工程师复核来界定成果边界。
