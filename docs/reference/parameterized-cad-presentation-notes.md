# 参数化 CAD 生成系统汇报稿

## 使用方式

这份稿子用于线上汇报时提词。页面切换以交互 HTML 为准，看到“【点击……】”时点击对应目录或卡片。代码不需要逐行朗读，重点说明它在系统中承担什么职责。

---

## 一、开场：项目标题和定位

【打开封面】

今天汇报的项目叫“基于参数化构造过程与几何验证的工程设计辅助系统”。这个标题里有三个关键词。

第一是“参数化构造”：系统不是只生成一张看起来像零件的图片，而是先识别零件的尺寸、孔位、接口和约束，再用参数生成一个可以继续修改的 CAD 模型。比如把板的宽度从 150 毫米改成 180 毫米，孔位和相关特征应该按照规则重新计算。

第二是“几何验证”：模型生成的参数和建模步骤必须经过 CAD 内核、实体有效性、STEP 回读和零件族规则检查。系统可以判断模型是否构造成功、孔位是否越界，但首期不把结构强度、安全认证或有限元结论作为承诺。

第三是“工程设计辅助”：它的定位不是替代工程师，也不是做任意零件的通用 CAD 软件，而是在一个数据和规则经过核验的零件族内，帮助工程师把需求快速转成可检查、可编辑的设计初稿。

## 二、项目背景：参考的三类工作

### 1. SKY-001：面向工程的 World Model

【点击“问题定义”】

SKY-001 关注的是工程对象的构建过程。公开介绍里可以分成三类任务来理解，它们是三种任务形态，不是三个独立产品。

第一类是 CAD 装配层级任务。输入可以是产品图像以及产品的上下文，模型先理解整体由哪些组件和零件组成，再形成装配或零件层级，同时预测逐步的 2D 草图和 3D 状态。它解决的是“复杂产品如何拆成层级并逐步构建”。

第二类是 CAD 零件构建任务。输入是零件或父级上下文，输出是建模过程中不同阶段的草图和 3D 中间状态。它更关注一个零件怎样从草图逐步变成最终形状。

第三类是 BIM 构建任务。输入是建筑轮廓、布局等信息，输出是房间或空间层级，以及按顺序生成的平面图状态。它解决的是建筑空间布局和构建过程。

SKY-001 的启发是：工程建模不只是最终结果，还可以建模“构建过程”。但它公开展示的输出主要是视觉状态序列和层级关系。把草图进一步转成可执行 CAD 操作，并保留可编辑的原生特征历史，仍被公开文章列为后续方向。因此，它和我们项目的重点不同：我们不做通用视觉世界模型，而是直接把一个零件族的结构化参数送入确定性 CAD 构造和验证流程。

### 2. Seek-CAD

Seek-CAD 采用训练无关的思路，使用本地推理模型生成 SSR 组织的 CAD 程序，再通过 CAD 几何内核执行。它还把执行后的模型渲染成逐步视图，让视觉语言模型检查生成结果，再把文本和视觉反馈交给模型进行有限修正。

它主要解决的是：在不微调主模型的情况下，怎样利用检索、几何执行和视觉反馈提高 CAD 程序生成质量。它的优势是反馈循环和较丰富的建模表达；但它依赖特定的 SSR 表示、CAD 执行环境和反馈服务，也不是针对某一个工程零件族建立的确定性规则系统。

### 3. FutureCAD

FutureCAD 研究的是 LLM 驱动的程序化 CAD 生成。它使用 Qwen2.5-7B 做监督微调和强化学习，生成 CadQuery 程序；同时训练 BRepGround，根据文字查询定位当前 B-Rep 模型中的边或面，辅助选择圆角、倒角和抽壳等拓扑操作。

它关注的是程序生成和 B-Rep 实体定位，目标范围比我们的首期范围更广，训练和标注需求也更高。它说明了语言模型可以参与 CAD 程序和拓扑实体选择，但论文中的训练规模和指标不能直接外推到我们的单一零件族。

### 4. 我们要解决的工程问题

在这三类工作的基础上，我们把问题收窄为：针对一个经过数据和许可核验、最终冻结的零件族，把自然语言需求转换为可检查的参数、依赖和约束，再由确定性 CAD 构造器生成可编辑模型，并验证参数修改后特征关系是否仍然成立。

我们的区分点有四个：

1. 不复现 SKY-001 的通用工程视觉世界模型；
2. 不直接复制 Seek-CAD 的通用 CAD 代码自修订路线；
3. 不以 FutureCAD 那样的通用程序生成和 B-Rep 学习为首期目标；
4. 把 Typed CAD IR、确定性编译器和 CAD 内核验证作为主线，模型只负责结构化理解和参数候选。

## 三、首期候选零件族与决策门

【点击“首期候选零件族与决策门”】

首期不同时做三个方向，而是先比较，再冻结一个零件族。决策门主要看四件事：数据和使用许可是否可核验，参数规则是否清晰，几何生成是否可控，应用价值是否明确。还要用真实样本跑一次 CAD 内核，不能只凭目录或想象决定。

### 1. 工业铝型材框架角码和连接板

这个方向的数据获取相对容易。厂商目录、尺寸表、系列规格和部分 CAD 文件比较容易找到，数据通常有较明确的尺寸和接口关系。

它的应用也很具体，包括自动化设备机架、防护围栏、工装台和机器人工作站框架。生成时主要要处理型材槽宽和系列、连接方式、孔槽布局以及紧固件接口。首期可以先限定少数型材系列，因此规则比较容易收紧。

所以它是当前建议优先验证的方向：数据结构相对规整，应用场景明确，几何生成难度也相对可控。

### 2. 机器人末端工具安装转接板

这个方向的用途价值比较高。它用于连接机器人末端法兰和夹爪、吸盘等工具，能够支持末端工具快速更换和接口适配。

难点在于数据分散。不同机器人品牌和型号有不同的法兰孔系，不同工具又有自己的接口尺寸，需要同时处理中心定位、螺纹或通孔、孔距、板厚和安装方向。厂商资料和 CAD 文件虽然存在，但需要逐项核验，不能把不同型号的数据混在一起。

因此，它适合做数据核验通过后的备选方向，价值高，但首期数据整理和接口规则工作量更大。

### 3. 电机安装板和支架

电机安装板也有明确的工业用途，例如固定电机并把它集成到设备或机架中。数据可以从厂商样本、安装尺寸表和部分 CAD 文件获得。

它的难点是装配关系更复杂，需要同时考虑安装孔距、轴线对中、底脚或法兰形式，以及与周边零件的间隙。若把适用电机型号和安装方式限定得足够窄，它可以做；但相较铝型材连接件，首期的生成边界需要收紧。

## 四、完整版：目标和 12 周范围

【点击“方案 A：完整版”】

完整版的核心目标不是训练一个大模型，而是在 12 周内完成一个单一零件族的完整研发验证。

第一，输出可编辑的参数化设计，而不是固定尺寸的 CAD 结果。

第二，在冻结的零件族内验证几何规则和接口规则，保证输出不是只在视觉上相似。

第三，评估小样本检索和有限模型适配是否有实际收益。这里不宣称元学习，也不宣称可以直接泛化到新的零件族。

12 周范围内需要完成四件研发工作：

1. 建立云端和本地模型基线；
2. 构建一个来源、许可、参数真值和分组切分都可追溯的小型 CAD 数据库；
3. 在确定性 CAD 闭环稳定后，完成一次有界的 LoRA/QLoRA 监督微调对照；
4. 在构造器和验证器稳定后，完成一次小规模 RL 可行性实验，判断 CAD 执行奖励是否带来可测增益。

这里的“完成 RL 实验”不等于必须得到正向结果。如果奖励噪声太大、CAD 执行太慢或有效样本不足，就记录为当前资源和数据条件下不可判定或不值得继续。首期不做从零预训练、1B 级自建解码器、万级 rollout、多零件族并行交付，也不做工业级仿真认证。

## 五、系统架构：从输入到输出

【点击“系统架构”】

### 1. 用户输入

系统主要接收自然语言需求，例如“生成一块用于安装的连接板，宽度 150 毫米，厚度 12 毫米，四角有安装孔”。参考图像或草图可以作为补充线索，但没有尺度信息时不能直接推断精确尺寸。

还有一种输入是示例零件。这里优先指带参数和 CAD 信息的示例，而不只是图片。用户可以提供三到五个相近的 CAD 样本，系统根据尺寸、孔数、孔位和特征类型检索相似样本，帮助用户确认模板或参数范围。示例只是参考，不会直接被当成新的设计规则。

### 2. 为什么同时保留云端和本地基线

这两个基线回答的是不同问题。

云端基线代表部署负担较低时较强通用模型可以达到的能力上限，用来判断参数抽取、缺失信息识别和约束理解是不是主要瓶颈。本地基线代表成本可控、数据可以留在本地、未来可以做适配的部署路径，用来判断小模型配合 Schema 和规则是否已经够用。

云端模型在项目启动时如果可用，可以优先评测 GPT-6.1 或 GPT-6；GPT-5.5只作为已有评测结果的历史参照，不因为论文使用过就默认它更好。

本地可以用 Qwen3-8B 代表较低资源档，用 DeepSeek-R1-Distill-Qwen-14B 代表更强推理但更高资源档。选择它们的目的不是预先认定最佳模型，而是观察性能和成本曲线。所有模型都要使用同一测试集、同一字段口径和同一验证流程比较。

### 3. 参数提取与判断

模型先把自然语言整理成参数 JSON。Schema 和 Pydantic 检查字段和类型，单位归一化把毫米、厘米等写法统一，规则层检查参数边界和接口约束。

如果用户没有提供厚度、孔径或法兰型号等关键输入，系统应该追问；如果孔位越界或孔径与板厚冲突，系统应该拒绝或要求修改。这里的原则是：模型可以提出候选，但不能把未经确认的工程假设伪装成用户要求。

### 4. 参数化序列生成

这一部分是从“参数已经检查通过”到“可以交给 CAD 后端执行”的关键准备环节。

如果使用固定值，建模序列可能是“画一个 150×150 的矩形，再拉伸 12 毫米”。这样的序列只能得到一个固定版本。参数化方式会把宽度、长度和厚度写成参数引用，例如 `params.width`、`params.height` 和 `params.thickness`。这样改变参数后，相关特征可以一起更新。

系统先用 Typed CAD IR 表达特征节点、参数、单位、依赖和约束。然后由确定性编译器把 IR 转成白名单内的 CadQuery 操作。模型不直接输出并执行任意 Python 代码。这样可以让模型负责理解意图，让编译器负责组织操作，让 CAD 内核负责构造几何。

最后会记录运行日志和版本信息，包括输入、参数、IR、模板版本、CAD 操作、错误原因、验证结果和输出文件位置，保证结果可以复现和定位问题。

### 5. 模型实验和训练边界

模型实验分成三层：先做云端和本地基线评测，再做一次有界 QLoRA 对照，最后做一次小规模 RL 可行性试验。

QLoRA 的目标是让本地模型更好地输出参数 JSON 和 Typed CAD IR，而不是训练 CAD 几何内核。RL 则把 CAD 执行成功、B-Rep 有效和约束满足转成奖励，比较 SFT 和 SFT+RL。训练规模、rollout 数量和 GPU 时间都由小试跑后封顶，避免在 12 周内把项目变成大规模模型训练项目。

### 6. 组件 4：小样本检索适配层

这个组件不是元学习，也不是让系统凭三个样本学会一个全新几何族。

它的工作方式是：用户提供三到五个带参数的参考零件，系统在已经冻结的零件族和参数空间内检索相似样本，展示参考样本及其参数，用户确认后仍然由确定性特征图生成新设计。

实现上可以先按归一化尺寸、孔数和布局、特征类型以及 CAD 几何描述符进行检索。样本量小的时候不需要引入复杂的点云网络。评测时比较无样本、检索样本和人工选模板三种条件，看参数准确率、约束通过率和建模时间是否稳定改善。没有稳定收益就不把检索模块纳入主流程。

## 六、数据、资源和时间估算

【点击“数据与样本构建”】

数据规模先从 100 个可审查实例试跑开始，覆盖合法边界、典型拓扑、缺失输入和非法约束。如果自动生成、内核检查和人工抽查都稳定，再根据吞吐和评测需要扩展到 200 到 500 个。800 到 1500 个不是首期前置要求。

每个样本不仅要保存参数 JSON，还要保存 Typed CAD IR、CadQuery 脚本、CAD 内核结果、STEP 文件、固定视角渲染图、约束断言结果以及来源和版本信息。数据按参数族和拓扑分组切分，避免同一模板的近重复变体同时出现在训练和测试中。

【点击“计算资源估算”】

确定性 CAD、规则验证和数据整理主要使用 CPU。API 模型路径不要求本地 GPU；本地 7B 或 8B 量化推理和小规模 QLoRA 可以使用实验室 A100、消费级 GPU 或短租云 GPU。RL 的 rollout 还依赖 CPU 并行执行 CAD，GPU 并不能解决所有瓶颈。

训练时间不预设一个固定的 GPU 小时数，而是先测单步时间、有效 batch、CAD 执行耗时、奖励有效率和失败重试，再根据实际吞吐外推。资源不足时，优先保证确定性 CAD 主线，再把训练实验控制在封顶预算内。

## 七、技术验收指标和失败处理

【点击“技术验收指标”】

主要指标有五类。

第一是参数提取准确率。不能只看零件类型对不对，还要逐字段检查尺寸、单位、孔位和接口类型。

第二是输入判定正确率。合法输入应该接受，关键参数缺失或约束冲突时应该追问或拒绝。误接受一个不完整设计，通常比直接拒绝更危险。

第三是构造可执行率。Typed IR 能否成功编译并运行 CadQuery。

第四是合法输入几何有效率。模型运行成功后，还要通过实体闭合性、非零体积和 STEP 回读。几何有效不等于结构安全，所以这个指标不能被表述成工程安全保证。

第五是约束保持率。对固定测试集做多次合法和非法参数修改，检查孔位、边距和特征依赖是否按预期保持。

如果加入检索，还要报告检索相对无检索是否带来稳定增益，不能只看一次成功案例。

常见失败包括极端参数组合、冲突约束、超出首期零件族范围以及自然语言歧义。系统的处理方式是说明失败原因、给出参数调整建议，并允许用户手动修正，而不是自动编造一个工程结论。

## 八、轻量版：低负担交付路径

【点击“方案 B：轻量版”】

轻量版和完整版共用在线 CAD 生成主干：Prompt、Schema、Typed CAD IR、确定性编译器、CadQuery/OCP 和验证器都保留。

它的低负担主要体现在：主线不训练模型，不做专门的视觉融合器，不建设通用 CAD 训练集，也不把 QLoRA 和 RL 作为交付依赖。它主要使用云端或本地模型的零样本、少样本检索和有限验证修复，在一个冻结的零件族内交付可演示系统。

### 1. Prompt 设计

【点击“组件 1：LLM 推理引擎”】

Prompt 不是 CAD 建模格式，而是对模型的任务说明。System Prompt 规定模型要提取明确参数、标记来源、识别缺失信息和遵守项目规则；User Prompt Template 把当前用户需求填进去，要求模型输出结构化 JSON。

这个 JSON 还不是 CAD 模型，也不是直接执行的 Python 代码。它之后要经过 Schema/Pydantic 校验，再转换成 Typed CAD IR。因此轻量版不是“Prompt 直接生成 CadQuery”，而是：

```text
Prompt → 参数 JSON → Typed CAD IR → 确定性 CAD 模板
```

### 2. 有限验证与字段修复循环

【点击“组件 2：有限验证与字段修复循环”】

代码示例表达的是一次请求内的“生成—构造—验证—修复”循环。模型先输出参数 JSON，程序把它转换成 Typed CAD IR，再调用白名单编译器和 CAD 构造器。如果构造或规则检查失败，就把机器可读的失败字段反馈给模型，只允许有限次数修复。

这不是强化学习，因为它不会更新模型参数，只修复当前这一次请求。渲染多视图和 VLM 只做外观和语义一致性辅助，尺寸、拓扑和约束仍由 CAD 内核和规则验证器负责。达到最大尝试次数还失败，就返回明确的拒绝原因。

### 3. CadQuery 确定性构造器

【点击“组件 3：确定性 CAD 生成器”】

代码示例是一个连接板构造模板。它先归一化参数，计算孔位，检查孔到边缘的距离，再用 CadQuery 建立板体和孔的切削体，最后进行布尔运算、实体有效性检查和 STEP 导出。

这个模板不是让 LLM 每次临场写代码，而是项目预先编写、测试和版本化的零件族构造器。Typed CAD IR 的特征节点由确定性编译器映射到这类白名单模板。这样同样的 IR、参数和软件版本可以得到可复现的构造过程，也降低模型生成任意代码的风险。

### 4. 后续部分简述

后面的研究对比、资源估算、API 成本、技术验收指标和风险表，主要用于说明轻量版的边界和可交付性。轻量版重点是先把参数抽取、确定性构造、验证和有限修复跑通；它不宣称跨零件族泛化，也不把视觉模型、仿真和大规模训练作为首期依赖。

## 九、两个版本的取舍

【点击“两版本技术对比”】

两版不是两套不同的 CAD 系统，而是同一在线主干的两种研发范围。

完整版增加了可追溯 CAD 数据库、QLoRA 对照和 RL 可行性实验，研究问题更完整，但训练收益、数据质量和资源消耗都存在不确定性。

轻量版不训练交付模型，主要依靠 Prompt、Schema、Typed CAD IR、确定性模板和验证器，负担更低，更适合在 12 周内形成稳定演示和工程闭环。

如果目标是先拿到可靠成果，可以以轻量版作为交付主线，同时保留完整版的数据、评测和 IR 资产；如果导师更重视研发对照，再在闭环稳定后执行完整版的有界实验。

## 十、交付物

【点击“项目交付物”】

完整版交付包括：版本化 Typed CAD IR、确定性编译器、验证器、单一零件族数据和数据生成流程、后端 API、前端界面、部署配置、技术报告和 API 文档。

如果 QLoRA 实验实际有效，再交付适配器权重、训练配置和复现实验记录；如果没有稳定收益，就交付实验报告和失败分析，不强行把模型权重接入系统。

这里不展开论文投稿，首要交付仍然是可运行、可检查、可复现的系统和实验资产。

## 十一、总结和后续潜力

【点击“总结”】

这个项目的核心不是让模型自由生成任意 CAD，而是把自然语言需求、参数、约束和确定性几何构造连接起来。

短期内，它可以用于单一零件族的快速方案生成、规格变体生成、参数修改和工程师初审。例如铝型材连接件可以帮助自动化设备机架和工装台快速生成规格变体；机器人转接板可以辅助不同法兰和工具接口之间的适配；电机安装板可以辅助设备集成中的重复设计。

后续如果数据、接口规则和验证能力继续积累，可以扩展到相邻零件族、更多输入形式和更复杂的装配关系。再往后，才有条件考虑更强的视觉理解、跨零件族泛化、B-Rep 实体交互和仿真接口。但这些扩展都需要独立数据和验证，不能从首期单一零件族的结果直接推断出来。
