### 2026-10-30 / PLAN-001 / 数据源判断与推进节奏

- 参与者：项目负责人、总体规划 Agent
- 本次目标：根据 `database/` 中的研究与接入计划，判断当前开源数据源是否足以启动系统，并提出从数据、接口到评测的推进节奏。
- 已确认：根据仓库资料，本轮讨论对象应是 BenchCAD 2.0 GitHub 社区参数化零件族，而不是 Public/Core 评测集；社区族的 `part.py`、`spec.py`、`family.json`、参数范围、约束和确定性 `build()` 与本项目的“参数—规则—几何”主链高度匹配；Public/Core 受用途限制，不能作为本项目训练、检索语料或公开样本库；当前 `database/` 只有研究/计划文档，没有实际族源码、固定 commit、项目 manifest 或运行结果；资料记录的 4/150 merged、0 release-qualified 是截至 2026-08-02 的历史状态，实施前仍需重新核验。
- 候选方案与取舍：建议采用“决策门 + 纵向切片”的节奏：先冻结数据边界和首个族；再完成一个族从来源、Schema、Typed CAD IR、原生 `build()`、STEP/几何验证到运行日志的最小闭环；随后用第二个结构不同的族检验 family adapter 和 IR 的公共/特异边界；在确定性主链稳定后，才建立检索样本集、自然语言任务集和 LLM 对照。这样比先做 Prompt 或大规模样本更早暴露接口风险。替代方案是先做两族并行适配（覆盖更快但返工风险更高），或先做 LLM/Prompt 演示（反馈快但无法证明 CAD 主链正确）。以上是推进建议，不是正式任务状态。
- 依据与假设：依据 `database/README.md`、`database/benchcad-dataset-first-plan-2026-10.md`、`database/benchcad-2-deep-dive-2026-10.md`、`database/cad-dataset-suitability-2026-10.md` 及项目状态/计划/任务文件；假设用户所说的“开源可用数据集”就是上述 BenchCAD 社区族。若用户指的是另一数据源，需要重新判断。
- 未决问题/需要确认：具体首个族和第二个族；源仓库 commit、许可证和当前状态；是否接受“先一族纵向切片、再第二族泛化”作为推进节奏；首期是否只覆盖参数化工程零件生成，不扩展到图/网格重建；可公开发布的是源引用、Schema、生成代码、样本 ID 和验证结果，还是还包括派生样本。
- 建议下一步：先讨论并确认四个门：数据门（来源/版本/许可/可运行）、接口门（manifest/Schema/IR 最小字段）、几何门（构造/STEP/规则验证）、评测门（Oracle → 无检索 LLM → 同族检索）。在数据门通过前，不进入全量样本和 Prompt 优化。
