# 总体架构与推进方案比较

本文件由 PLAN-001 规划 Agent 按讨论主题追加。每个方案应记录适用前提、依赖、收益、风险、未决问题和是否已获项目负责人确认。

当前暂无已记录方案。

## 2026-10-30 / BenchCAD 首期推进范围（草案）

以下比较只用于讨论，不构成 ADR 或正式范围变更。

| 方案 | 适用前提 | 依赖 | 收益 | 主要风险 | 当前建议状态 |
|---|---|---|---|---|---|
| A. 两族门控后扩展 | 项目负责人接受先交付最小闭环 | 先完成两个结构不同族的状态/许可/环境核验与 smoke test | 将 IR、adapter、构造、验证和评测风险集中在可控范围；失败可回滚到一族 | 早期覆盖面较小，需明确扩展决策门 | 建议草案，待确认 |
| B. 全部当前可用族首轮覆盖 | 族级接口已经稳定且资源充足 | 并行完成全部族审查、适配和切分 | 早期展示多族覆盖，减少后续迁移成本 | 许可、环境、参数异构和测试泄漏风险同时放大 | 备选草案 |
| C. 单一垂直族优先 | 导师要求先证明一个行业场景 | 需重新选择并核验垂直族来源、规则和数据 | 任务语义集中，演示路径短 | 偏离当前 BenchCAD 多族建议，开放性和可迁移性较弱 | 备选草案 |

### 当前取舍判断

基于现有仓库证据，A 更符合两三个月轻量版约束和 ADR-0005 proposed 的“先两个结构不同族、再按进度扩展”表述；B 只有在族级审查和接口资源已确认时才适合；C 需要新的范围决策，不能由 PLAN-001 自行切换。三者都需要项目负责人确认，且正式范围变化须由 Codex 中枢建立或更新 ADR。
