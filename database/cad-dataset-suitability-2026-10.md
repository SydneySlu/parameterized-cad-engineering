# 轻量化参数化 CAD 项目数据集适配性评估

- 日期：2026-10-28
- 任务：DATA-001
- 状态：阶段性研究结论；不冻结首期零件族、不改变 ADR-0002
- 评估对象：BenchCAD 2.0、CADBench（附件论文 arXiv:2605.10873v2）、Seek-CAD 数据集

## 结论先行

对于当前轻量版系统（LLM 结构化抽取 + 小样本检索 + Typed CAD IR + 确定性 CAD 构造/验证），优先把 **BenchCAD 2.0 的社区零件族数据**作为主数据源候选。它的样本接口直接包含参数定义、来源范围、约束检查和确定性 CadQuery 构造，能支持项目最关键的“参数—规则—几何”链条，许可说明也明确区分代码与数据：仓库代码/设计为 MIT，发布的数据制品为 CC BY 4.0。其当前已合并族数量仍小，不能仅因标称 150 个工业零件族就假定 150 族都已公开可用；建议先挑一个具体族做接入试点，再决定是否围绕三个候选方向之一扩展。

把 **CADBench**作为独立的几何重建/多模态评测参考源，而不是首期参数检索库或参数化监督训练集。它有 18,000 个评测样本、几何文件和多模态输入，但其论文目标是从图像/网格重建可执行 CAD 程序；样本不等价于带工程参数、来源范围和接口约束的产品族。其许可按源数据混合，公开发布项目衍生数据前必须逐项追踪源许可。

把 **Seek-CAD**作为 CAD 特征序列、SSR 表示、描述—程序配对和检索机制的研究参考；可做小规模数据格式试读和表示映射验证。它公开约 40,000 个 JSON CAD 模型及 23,313 个 Text2SSR 配对，但数据许可在作者 README/仓库许可证中没有清楚单独标示；GitHub 仓库代码 MIT 不等于数据 MIT。其 SSR 与工程参数/约束 Schema 也不相同，因此接入项目 IR 仍需映射和筛选。

**推荐数据策略：**主线从一个许可证清晰、参数语义完整的 BenchCAD 2.0 零件族开始；CADBench 用于补充几何重建指标和输入模态压力测试；Seek-CAD 用于参考特征序列和检索样例，不把它作为未经许可核验即可再发布的训练语料。若 BenchCAD 2.0 中没有和最终方向匹配的族，优先按其家族贡献规范扩展一个来源可追溯的族，而非先把三个数据源混成一个不一致的大库。

## 项目需求与比较口径

轻量版首期不依赖训练生成模型。数据首先要支持：

1. 为少样本检索提供可理解、可追溯的描述和 CAD 示例；
2. 对参数、单位、范围、默认值来源和参数间约束建立规范；
3. 用确定性构造器生成可编辑 CAD，并由几何内核及规则验证；
4. 允许复现实验、公开代码和必要数据，同时不把不可再分发资产混入开源包。

因此评估重点不是原始样本数量，而是字段语义、特征/参数可映射程度、目标零件族的覆盖、许可清晰度、下载/清洗成本和可复现评估价值。

## 各数据集详析

### 1. BenchCAD 2.0

需要区分 BenchCAD 2.0 的两个相关但不同资产：

- 项目仓库 `BenchCAD-org/benchcad-2` 是社区零件族的数据/生成管线。一个族由构造函数、参数规范、约束函数和来源说明构成；框架负责采样参数并产出可执行 CAD 程序和渲染。README 写有“150 industrial part families”的目标/项目定位，但仓库状态页（访问时更新于 2026-08-02）显示仅 4/150 已合并。因此应按具体可下载族核验，不应将目标总数当作目前现成数据量。
- 博客所称 Public set 是 100 个公开任务案例，用于尝试 harness；作者说明 Public 分数不可报告。Core 是 100 个留出案例，需签 evaluation-only agreement。博客任务包含工程图到零件/装配、视图到零件/装配、PCB 图像到电路连接等，是评测任务，不等于 150 个可直接用于检索的参数化族。

它最适合项目的原因是数据结构与轻量版的系统边界一致：参数提取结果可以映射到显式参数；范围、来源与 `check()` 约束可以转成 Schema/规则验证；`part.py` 可作为确定性构造器的审计参考；框架派生的程序能提供参数变更与几何之间的可复现关系。它也提供高质量扩展流程，包括标准/产品数据、工程图、参数表、几何复核和人工审核。

局限是数据量和已覆盖类别可能很小，且样本是“由人审过的参数化零件族”，不天然提供大量真实用户自然语言请求，也不等价于开放域 CAD 语料。公共 100 案例是任务评测材料，Core 受协议限制，不能把 Core 当作公开训练数据。对于项目，最有价值的可能是从其中拿一个结构相近的族作为格式范例，选定自己的工程类别后按同样严谨度扩展。

### 2. CADBench（论文附件）

附件论文是 CADBench，而非 BenchCAD 2.0。CADBench 将 DeepCAD、Fusion 360、ABC、MCB 和 Objaverse 等来源整理为 18,000 个测试样本，覆盖 CAD-Base、CAD-Fusion、CAD-Extrude、CAD-All-Ops、CAD-Mechanical、CAD-Organic 六组；提供网格/图像输入和 STEP 等目标资产，并比较重建几何、可执行性和程序紧凑度。它主要回答“给定图像或网格，模型能否重建可执行的 CAD 程序”，不直接回答“从工程意图中抽取一组参数、遵守接口尺寸和行业规则并生成目标零件族”。

对轻量版的直接价值是借鉴评测：除 STEP 是否成功导出，还可检查几何相似度、程序执行率、复杂度分层、输入模态变化的影响。可以选其适合且许可允许的某些来源做外部测试，但不应一开始下载整个约 80 GB 包，更不应将其 18,000 个测试样本称为项目训练集。可先抽样查看 CAD-Mechanical 或 CAD-Extrude 的标签、几何和程序可得性，再定义小型外部验证集。

许可边界尤其关键：论文写明不同来源遵循各自许可；Fusion 360 限非商业研究，Objaverse 对象需逐对象核对许可。CADBench 代码仓库自身 MIT 不会覆盖数据源许可。若本项目未来开源，建议只发布自建转换代码、样本 ID/来源清单和允许再分发的派生物；对限制性源数据则提供官方下载脚本或说明，不打包、不镜像。

### 3. Seek-CAD

Seek-CAD README 声明约 40,000 个 JSON CAD 模型，覆盖 sketch、extrude、revolve、fillet、chamfer、shell 等操作，约 70% 含高级操作；另提供 23,313 个 Text2SSR 描述—程序配对。论文中使用的 10,000 个本地检索样本是一次实验配置，不能当作数据集总量或唯一公开划分。

它比 CADBench 更接近“具有构造过程的参数化 CAD”，可帮助理解特征节点如何表示、如何将文本与建模步骤配对、如何用检索示例引导生成。可是其 SSR 表示不是项目 Typed CAD IR，程序字段还要转换与验证；自然语言描述与“工程意图规格”之间也有差别，未见统一的行业参数范围/接口公差/来源约束标签。故其样本不应未经适配就加入项目主检索库。

公开仓库的代码许可为 MIT，但 README 对数据没有明确单独许可声明。对本项目私下阅读/实验的可行性和对外分发、开源权利是不同问题；在拿它做公开派生集或发布项目数据包前，应联系作者确认数据许可及 ABC 派生数据的再分发条件，并记录答复。未确认前可把它用于方法参考和本地格式试验，不把原始数据镜像到项目仓库。

## 推荐的分阶段用法

### 阶段 A：低成本侦察（先做，不冻结零件族）

1. 核对 BenchCAD 2.0 当前已合并的 4 个族、开放 family issue、Public 100 案例的数据卡和协议；挑 2–3 个结构接近候选族的样本做人工审查。
2. 下载 CADBench 的 README/数据卡与少量允许使用的样例元数据，确认程序目标、标签、许可证及磁盘/转换成本；不先下载完整 80 GB。
3. 对 Seek-CAD 先读取公开 README、示例和 JSON 结构；抽查少量记录，形成 SSR→Typed CAD IR 的映射难点清单；许可确认前不再发布数据。
4. 对三个候选工程方向分别记录：匹配到的现有族/样本数、可直接获得的尺寸来源、构造特征覆盖、仍缺少的参数和规则。

### 阶段 B：一族试点

选择与导师和项目负责人最终确定的零件方向匹配、来源可审计、参数结构不太复杂的一个 BenchCAD 族或仿照它新增的族；把它转成项目统一 manifest：

`source/license → family_id → parameter schema/unit/range/default provenance → constraints → Typed CAD IR → deterministic builder → STEP/render → validation result`

首期重点是同一族内部的合法参数变化、参数缺失追问、构造成功、几何/接口规则和版本化记录。检索样例只保留少量多样实例，不用未经清洗的全集替代规则设计。

### 阶段 C：扩展或外部验证

- 若目标族在 BenchCAD 中已存在：扩展参数覆盖和评测样本，确保新样本不是训练/检索近重复。
- 若没有：按 BenchCAD 的社区族规范补一个具体类别，新增标准/厂商资料、尺寸表、构造代码、约束和人工审核记录。
- 从 CADBench 中建立许可允许的外部几何基准，评估 CAD 输出几何与程序可执行性；它不能替代项目自己的参数抽取和工程约束测试。
- Seek-CAD 在取得数据授权且映射完成后，再作为可选的特征序列/文本检索补充。

## 下一步需要导师/项目负责人讨论的门槛

1. 首期目标是“参数化工程零件族生成”还是“图/网格重建 CAD”？当前轻量版架构更支持前者。
2. 是否接受将 BenchCAD 2.0 的可审计社区族作为建模和数据标准，并在其上扩一个窄类别？
3. 三个原候选方向中，哪一个能找到最可靠、可公开引用的规格表/标准资料，并能写出可核验的几何约束？
4. 是否需要公开原始样本，还是公开 schema、生成代码、来源、样本 ID 和验证结果即可？
5. Seek-CAD 数据许可是否能取得书面确认；若不能，是否仅作为论文/方法参考？
